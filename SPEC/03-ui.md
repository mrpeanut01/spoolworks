# SPEC-03 — UI/UX Specification of the Windows CFS-RFID App

Reverse-engineered from `Windows/CFS-RFID/*` (WinForms, .NET Framework 4.8.1, `CFS-RFID.csproj:11`).
Purpose: enough fidelity to rebuild the app in SwiftUI for macOS with functional parity.

All line references are `path:line` relative to the repo root.

---

## 0. Screenshot reading (`Windows/winapp.jpg`)

The bundled screenshot (referenced by `Windows/README.md:14`) shows an **older build** of the main
window. Described exactly as seen, top to bottom:

- Windows 11 title bar, light grey. Left: circular app icon (dark ring / blue-grey disc), title text
  **"CFS RFID"**. Right: minimize, maximize (greyed/disabled look), close.
- **Icon toolbar row** — five flat, borderless blue icon buttons across the full width, evenly
  spaced: (1) download — a circle with a down-arrow inside; (2) upload — an up-arrow over a
  baseline; (3) trash can (solid blue); (4) pencil; (5) large blue "+". All are line-art icons in a
  medium blue (`#1976D2`-ish) on the `#F4F4F4` window background.
- **Four stacked dropdowns**, full width, white fill, thin grey border, black text, large type,
  with a small square drop-arrow button at the right edge of each:
  1. `K2` (printer model)
  2. `Creality` (vendor)
  3. `EN-PLA+` (material)
  4. `1 KG` (weight)
- **Color swatch bar** — a wide flat rectangle filled mint/aquamarine green, no border, sitting
  directly under the weight dropdown. This is the color picker button.
- **Two switch rows**, label left / iOS-style pill toggle right, both shown in the OFF state (grey
  track, white thumb at left):
  - `Auto read tag on scan?`
  - `Auto write tag on scan?`
- **Tag row**: bold `Tag ID:` then a small **orange/amber closed padlock** glyph, then the UID in
  bold monospace-ish text `3A 63 33 03`. Far right of the same row: a blue "stacked layers with a
  diagonal slash through it" icon (the legacy *format tag* action).
- **Bottom action row**: two solid blue (`#1976D2`) rectangles with white bold text —
  **`Read Tag`** (left) and **`Write Tag`** (right), same size, separated by a gap.
- Overall: very tall/narrow portrait window, flat design, no group boxes, no menu bar, generous
  vertical rhythm, everything left/right aligned to a common margin.

**Delta vs. current code:** the current `MainForm.Designer.cs` replaced the download/upload icons
and the inline format icon with a hamburger **menu** button (`MainForm.Designer.cs:236-249`) that
slides out a left sidebar; those actions moved into the sidebar (`MainForm.cs:108-122`). The four
dropdowns, color bar, two switches, tag row and Read/Write buttons are unchanged. Build the macOS
app against the **current code**, not the screenshot.

## 2. Settings persistence (Windows Registry)

`Settings.cs` reads/writes **`HKEY_CURRENT_USER\CFS RFID\Settings`** (note: *not* under `Software\`)
— `Settings.cs:12, 24, 51, 63, 94, 106, 137, 152`. Four typed overload pairs exist: `bool` (stored
as `DWord` 0/1), `int` (`DWord`), `long` (`QWord`), `string` (`String`). All failures are swallowed
and return the caller's default.

## 4. Custom controls

### 4.1 `SwitchCheckBox` (`SwitchCheckBox.cs`)

An owner-drawn `CheckBox` rendered as an iOS-style pill toggle.

- Properties: `SwitchOnColor` (default `#1976D2`), `SwitchOffColor` (`LightGray`), `ThumbColor`
  (`White`), `BorderThickness` (`1`) — `SwitchCheckBox.cs:9-12`.
- Default size `50 × 25`, min `40 × 20`; used at `60 × 31` everywhere.
- Draws a rounded-rect track (`GraphicsPath` with 4 arcs), a border in
  `ControlPaint.Dark(track, 0.1f)`, and a circular thumb of `Height - 4` px inset 2 px, snapped to
  left (off) or right (on) — **no animation** (`SwitchCheckBox.cs:34-64`).
- Clears its own background to `Parent.BackColor` each paint (`SwitchCheckBox.cs:31-32`), so it
  visually blends with `#F4F4F4`.
- `Text` is set to `""`; the visible caption is always a **separate sibling `Label`** placed to the
  left. (Several designer files leave junk `Text` values like `"switchCheckBox2"` or a copy-pasted
  `"Auto read on tag scan?"`; these are never rendered.)

### 4.2 `TagBlockCard` (`TagBlockCard.cs`, `.Designer.cs`)

A `UserControl` "row card" used in the tag-memory list.

- Size `197 × 80` at design time; at runtime forced to `Height = 60` and
  `Width = panel.DisplayRectangle.Width - 10`, `Margin = (5,2,5,2)` (`TagMemoryForm.cs:83-85`).
- White background, `BorderStyle.FixedSingle` applied in `SetData` (`TagBlockCard.cs:18`).
- Layout: `picIcon` 76 × 74 at (3,3), StretchImage; `lblTitle` at (94,8) Segoe UI 11 Bold;
  `lblHex` at (94,49) Consolas 10.
- `SetData(title, hex, icon)` is the only API (`TagBlockCard.cs:13-19`).

### 4.3 `Toast` (`Toast.cs`)

A borderless, always-on-top, non-activating popup owned by the parent form.

- Background `#333333` normally, `#990000` when `isError` (`Toast.cs:150-157`).
- Text: white, **Arial 11 Bold**, centered both axes, custom-drawn in `OnPaint`
  (`Toast.cs:114-127`). Supports `\n`.
- Size auto-fits the measured text + `Padding(10,10,10,10)` (`Toast.cs:60-65`).
- Rounded corners via DWM `DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_ROUND` (`Toast.cs:22-23,67-69`).
- Animation: fade-in 200 ms → hold → fade-out 300 ms, 10 ms steps
  (`Toast.cs:28-30, 71-109`). Durations: `LENGTH_SHORT = 2000`, `LENGTH_LONG = 3500`
  (`Toast.cs:35-36`).
- Position: horizontally centered on the parent + 8 px, 30 px above the parent's client bottom
  (`Toast.cs:32, 134-140`). Repositioned as the main window moves
  (`MainForm.cs:853-859`).
- Only **one** toast at a time — showing a new one closes the current
  (`Toast.cs:146-149`). Static `currentToastInstance`.

### 4.4 `SmDialog` (`SmDialog.cs`) — fully code-built, no designer

See §5.9.

**Tab-order intent (as authored, messy).** Effective traversal is
`materialName(24) → btnColor(25) → materialWeight(26) → btnAdd(31) → btnEdit(32) → btnDel(33) →
printerModel(34) → vendorName(35) → btnMenu(41) → chkAutoRead(51) → chkAutoWrite(53) →
btnFrame(55) → [btnRead(22) → btnWrite(23)]`. The *visual* order is
printer → vendor → material → weight → color → switches → read/write. **The macOS port should use
the visual order**, which is clearly what was intended.

**Icon-button styling trick.** `btnDel/btnEdit/btnAdd/btnMenu` set both `BackColor` and `ForeColor`
to `#F4F4F4` (`MainForm.Designer.cs:193,196` etc.) and `MainForm_Load` re-assigns
`ForeColor = BackColor` (`MainForm.cs:62-65`) so any text is invisible; only the PNG shows.
`FlatAppearance.BorderSize = 0` on every button (`MainForm.cs:67-73`).

background (`MainForm.cs:861-864`), or **any mouse movement over the form**
(`MainForm.cs:887-890`) — an aggressive dismissal that feels twitchy and should not be reproduced
verbatim on macOS.

#### Load sequence (`MainForm_Load`, `MainForm.cs:37-105`)

1. Apply colors (`#F4F4F4` bg, white sidebar, `#1976D2` buttons/link).
2. Restore `AutoRead`/`AutoWrite` into the switches **before** wiring `CheckedChanged`
   (`MainForm.cs:47-50`) so restoring doesn't re-save.
3. If `ShowMain == false`: shrink window by 40 px, move `btnFrame` up 45 px, `isSmall = true`
   (`MainForm.cs:51-56`).
4. Seed `materialName.Text = "PLA"`, `materialWeight.Text = "1 KG"`, `MaterialColor = "0000FF"`,
   `btnColor.BackColor = #0000FF` (`MainForm.cs:58-61`).
5. Install tooltips (`MainForm.cs:75-79`); the encryption-key tip uses a **balloon** tooltip.
6. Populate `printerModel` from `GetPrinterTypes()` (filenames in `material_database\`, sorted —
   `Utils.cs:398-418`); select the saved `printerType` index, falling back to 0 on exception.
7. **Empty state:** if there are no printers →
   `Toast.Show(this, "Add a printer to get started", LENGTH_LONG, isError: true)` then a one-shot
   1000 ms `Timer` opens `ManageForm` (`MainForm.cs:93-103`).
8. `ConnectReader()`.

#### Reader connection states (`ConnectReader`, `MainForm.cs:305-381`)

`ConnectReader` is called on load and whenever the user clicks `lblConnect`

## 6. Reader & card monitoring UX (`Monitor.cs`)

`Monitor` is a thin wrapper over PC/SC's `ISCardMonitor` (`Monitor.cs:16-32`). It exposes three
events — `CardInserted`, `CardRemoved`, `StatusChanged` — but **`StatusChanged` is never
subscribed** by `MainForm`, so reader hot-plug/unplug is invisible: if the USB reader is removed,
nothing in the UI changes and the user must click `lblConnect`… which is hidden while connected.
**This is a real gap the macOS port should close** (see §8).

Flow, as surfaced to the user:

1. `ConnectReader()` enumerates `context.GetReaders()` and starts a `Monitor` over **all** of them
   (`MainForm.cs:326-333`). Any previous monitor is disposed first.
2. **Card inserted** → the whole UI reaction in `MainForm.CardInserted` (§5.1). Net effect the user
   sees: `Tag ID:` appears, the UID text appears, and a **padlock appears iff the tag is
   encrypted**. If `AutoRead`/`AutoWrite` is on, a read or write fires immediately and produces a
   toast. There is **no sound, no animation, no "tap your tag" affordance** — the UI is silent
   until a card arrives.
3. **Card removed** → `Tag ID:`, the UID and the padlock all disappear. **No toast.**
4. Errors during insertion are toasted; the outer `try/catch` in `CardInserted` /`CardRemoved`
   swallows everything else silently (`MainForm.cs:282, 301`).

The reader's buzzer can be toggled (`Reader.SetBuzzerOutputduringCardDetection`, `Reader.cs:80-85`)
but **is never called** — no audible feedback exists today.

## 8. macOS / SwiftUI adaptation recommendations

Opinionated, control by control. The rule: **keep every string, every state and every data path;
change every idiom.**

### 8.1 App shell

| Windows idiom | macOS replacement | Rationale |
|---|---|---|
| Single fixed `383 × 657` non-resizable window | `WindowGroup` with `.windowResizability(.contentSize)` and a **min width ~380, ideal 420, max ~560**; let height flex | Fixed-pixel windows read as broken on macOS. Content-size resizability keeps the compact feel while respecting Dynamic Type and localization. |
| Hamburger sidebar that slides in and auto-hides on mouse move | **`NavigationSplitView`** with a real sidebar (`.navigationSplitViewColumnWidth(min: 180, ideal: 200)`) plus the standard toolbar sidebar-toggle. **Delete the auto-hide-on-mouse-move behavior entirely** (`MainForm.cs:887-890`) | The auto-hide is hostile; macOS users expect a persistent, user-toggled sidebar with state remembered via `@SceneStorage`. |
| Sidebar section headers (Calibri 7 pt uppercase gray) | `Section("App") { … }` inside a `List(selection:)` with `.listStyle(.sidebar)` | Free, native, correct in both appearances. |
| Sidebar items open **modal dialogs** | Sidebar items should switch the **detail column** for the browsing screens (Manage Printers, Download/Upload Database), and stay modal only for genuinely transactional flows | Modal-per-menu-item is a WinForms habit; a split view makes the database screens feel like part of the app. |
| No menu bar at all | Add a real menu bar: **File** ▸ nothing; **Tag** ▸ *Read Tag* (⌘R), *Write Tag* (⌘W… avoid, use ⌘⇧W or ⌘T), *Format Tag…*, *Read Tag Memory* (⌘M); **Database** ▸ *Manage Printers…*, *Download Database…*, *Upload Database…*; **Filament** ▸ *Add…* (⌘N), *Edit…* (⌘E), *Delete* (⌫). Use `.commands { CommandMenu(…) }` | Keyboard access and discoverability are table stakes on macOS. Sidebar items become menu items *as well as* nav items. |
| `SettingsForm` as a modal dialog with a Close button | **`Settings { … }` scene** (⌘,) with a `TabView(.tabViewStyle(.grouped))`: *General* and *Spoolman* tabs mirroring `label1` / `label2` | This is the single most important divergence. Settings must be ⌘, and must not have a Close button. |
| `Program.cs` has no single-instance guard | Free on macOS — `NSApplication` is single-instance by default | Nothing to port. |
| `Environment.Exit(0)` on close (`MainForm.cs:930`) | Standard termination; put PC/SC teardown in `applicationWillTerminate` / a `.onDisappear` | Never hard-exit; the reader context must be released cleanly. |
| App icon from `app.ico` | Ship a proper `.icns` / Asset Catalog `AppIcon` with all sizes incl. dark-mode-safe margins | |

### 8.3 Layout, appearance, accessibility

- **Adopt `Form` + `.formStyle(.grouped)`** for MainForm's body. The four pickers, the color well
  and the two toggles map exactly onto grouped-form rows and will look native for free.
- **Drop all absolute coordinates.** Every position in §5 is authored at 9×20 font metrics; reuse
  the *grouping and order*, not the numbers.
- **Fix the tab order.** Use the visual order (printer → vendor → material → weight → color →
  toggles → Read/Write), not the authored `TabIndex` salad documented in §5.1.
- **Colors:** replace `#F4F4F4` window fill with the **system window background** and `#FFFFFF`
  sidebar with the **sidebar material** — do not hardcode light values or the app will be unusable
  in Dark Mode. Keep `#1976D2` **only** as an explicit brand accent (define it as an asset-catalog
  color with a light/dark pair, e.g. lighten to ~`#4A9EEA` on dark), and prefer
  `.tint(.accentColor)` so the app honors the user's system accent where it doesn't hurt brand
  identity. Map `IndianRed`/`MediumSeaGreen` to `.red`/`.green` semantic colors.
- **Fonts:** replace Microsoft Sans Serif / Calibri / Arial / Segoe UI with **`.body`, `.headline`,
  `.caption`** etc. Keep exactly one deliberate monospace: `TagBlockCard.lblHex` →
  `.font(.system(.body, design: .monospaced))`, plus the UID label.
- **Accessibility:** the current app has none — icon-only buttons with no text, a clickable label
  acting as a button, and status conveyed by a toast that a screen reader never sees. Every
  toolbar/sidebar item needs an `accessibilityLabel`; every toast needs an announcement; the
  padlock needs `accessibilityValue("Encrypted"/"Writable")`.
- **`Enabled` vs. hidden:** the Windows app hides controls it can't use. On macOS **disable and
  keep in place** (`.disabled(reader == nil)`) so the layout doesn't jump. Concretely: disable
  *Read Tag* / *Write Tag* when no card is present instead of letting them fire a
  `"Reader not connected"` toast; disable *Add to Spoolman* when the host is unset.
- **Kill the two window sizes.** `ShowMain` growing/shrinking the window by 40 px
  (`MainForm.cs:51-56, 535-551`) is a WinForms hack; with a `Form` layout, just conditionally
  include the toggle rows and let the window size to content.
- **Add the missing progress states.** `ManageForm` (`ManageForm.cs:25-47`), `UpdateForm`
  (`UpdateForm.cs:76-98`) and `TagMemoryForm` (`TagMemoryForm.cs:43-119`) all do async work with no
  indicator; `UploadForm` blocks the UI thread outright (`UploadForm.cs:135-208`). Use
  `ProgressView` + `.task`/`async let`, keep everything off the main actor, and add cancel.
- **Confirm the destructive delete** in Manage Printers (`ManageForm.cs:63-70` deletes with no
  prompt).
